# PolymathWizard/BHIL-AI-First-Development-Toolkit/03-sprint-workflow.md @ 161f8e5311bd

<!-- rcw:begin owner=source:src_a8c4bbb666585a6a85316b670ce64910 block=evidence -->
- The methodology mandates a test-first gate for AI-generated code: write tests, confirm they fail and commit that state, then implement without modifying test files. [@claim:clm_12b749dc1f0360ef014f0c64bbc9a34af1029f8baef28c4f52cab1799af67eff]
- For AI-native features, the methodology prescribes running a promptfoo eval suite before merging, with the pass threshold defined in the feature's SPEC acceptance criteria; unmet thresholds mean the task is not done. [@claim:clm_c5698cc0922bb2b43e84506d7ff25c6d2666d1f57189c5abd5f82b9172ca83c7]
- A sprint is defined as a two-week cycle with four phases: specification (days 1-2), planning (days 3-5), implementation (week 2 days 1-3), and integration/evaluation/deploy/retro (days 4-5). [@claim:clm_dfe5c310551a8491fba786290eca9de173a77b7e8ec36553d5581f721ae32a9b]
